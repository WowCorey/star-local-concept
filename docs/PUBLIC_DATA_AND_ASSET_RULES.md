# Public Data and Asset Rules

This is a public repository. Treat every committed file as permanently public and copyable.

## Allowed

- Clearly fabricated customer names, contact details and membership numbers
- Fictional venue names and layouts created for this prototype
- Fabricated menus, prices, promotions, points and event schedules
- Original icons, illustrations and design assets created for the concept
- Open-source or openly licensed assets with attribution where required
- Generic product categories that do not reproduce protected campaign artwork

## Prohibited

Do not commit:

- Real customer, employee or former employee information
- Real staff numbers, membership numbers, QR credentials or barcodes
- Dates of birth, phone numbers, addresses or payment details
- Screenshots from existing staff, loyalty, booking, POS or gaming systems
- Real employee benefits or internal terms
- Non-public venue layouts, rosters, stock levels, sales data or operational records
- Gaming-machine, exclusion, RSA, security or incident information
- Real API keys, tokens, passwords, certificates or environment files
- Copyrighted advertising artwork unless permission is documented
- Photographs supplied only as private design reference

## Synthetic-data standard

Synthetic data must not be a lightly edited version of a real person or record. Change the full combination of identity, contact details, behaviour, venue, dates, transaction values and identifiers.

Recommended reserved ranges and examples:

- Use `example.com` email addresses.
- Use obviously fictional member IDs such as `DEMO-1042`.
- Use fictional venue names such as `Harbour Family Hotel`.
- Mark prize values, prices and points as `Demo data` in the interface where confusion is possible.

## Reference-image rule

Existing-app screenshots and venue photographs may inform layout concepts privately, but they must not be copied into this repository. Recreate the underlying interaction as an original component using fabricated content.

## Before committing an asset

Confirm all four statements:

1. I have the right to publish it.
2. It contains no personal or confidential information.
3. It cannot authenticate or identify a real account.
4. It is necessary for the prototype.

If any answer is uncertain, do not commit the asset.
