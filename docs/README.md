# Project Documents

This directory is the source of truth for the prototype specification and public-repository rules.

## Current documents

- [`PUBLIC_DATA_AND_ASSET_RULES.md`](PUBLIC_DATA_AND_ASSET_RULES.md) — mandatory privacy, confidentiality and licensing rules.

## Planned documents

The following will be added before implementation begins:

- `STAR_LOCAL_PROTOTYPE_DESIGN.md` — screen, journey, fixture, visual and acceptance specification.
- `CODEX_BUILD_PROMPT.md` — the implementation instruction used to start the first Codex build.
- `DEMO_SCRIPT.md` — the five-minute meeting walkthrough.
- `ARCHITECTURE.md` — the final static prototype structure and deliberate limitations.

## Document hierarchy

When instructions conflict, use this order:

1. Public-data and safety rules
2. Root `AGENTS.md`
3. Approved prototype design document
4. Codex build prompt
5. Individual issue or pull-request instructions

The prototype design may evolve through review, but public-data and safety constraints are permanent unless explicitly replaced with stronger controls.
